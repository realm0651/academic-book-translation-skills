# Academic Book EPUB

## Scope

Use this skill after translation, whole-book Markdown assembly, and `COVER_SKILL` are complete. The body input is the single authoritative `master.md` produced by `TRANSLATION_SKILL`; the standard cover input is `cover_epub.jpg`. Images and image-based complex tables live under `assets/` and use relative paths.

Do not retranslate, rewrite, polish, renumber stable source footnote IDs, or maintain a second EPUB-specific body manuscript merely to fix presentation.

Bundled files:

```text
build_epub.py
epub_generic.css
epub_chapter_notes.lua
```

## 1. Core note model: native chapter-end footnotes

The assembled master may keep the Translation Skill source structure:

```text
# 第一章 ...
正文[^ch01-001]
...
# 第二章 ...
正文[^ch02-001]
...
# 注释
## 第一章
[^ch01-001]: ...
## 第二章
[^ch02-001]: ...
```

For EPUB, do **not** rebuild these notes as one cross-book endnotes chapter. `epub_chapter_notes.lua` removes only the source-side `# 注释` organizational shell and leaves Pandoc `Note` nodes untouched. Pandoc therefore emits the actual notes at the end of the XHTML chapter/chunk where they are cited.

Required link topology:

```html
正文……<a href="#fn1" class="footnote-ref" id="fnref1" epub:type="noteref">[1]</a>
...
<aside epub:type="footnote" id="fn1">
  <p><a href="#fnref1" class="footnote-back" role="doc-backlink">[1]</a>. 注释正文……</p>
</aside>
```

Required behavior:

- notes appear at the end of each chapter/chunk, not in one final Notes XHTML;
-正文 note links are same-XHTML fragment links (`#fnN`), not cross-file links;
-正文 markers are literal bracketed text such as `[1]`, not a bare `1` and not CSS-generated brackets;
-正文 markers are baseline text at the surrounding正文 font size, not superscript;
- each note begins with a visible bracketed backlink such as `[1].`;
- numbering restarts at 1 for each chapter/chunk generated by Pandoc;
- preserve EPUB3 `epub:type="noteref"` / `epub:type="footnote"` semantics.

The brackets are added only after Pandoc writes the native EPUB3 structure. Do not rewrite `Note` nodes into custom links merely to control appearance.

## 2. Navigation philosophy

EPUB navigation is a compact reading map, not a dump of every source heading, page marker, note number, or link.

Default policy for current translation masters:

- navigation normally shows two useful reading levels (`TOC_DEPTH = 2`): H1 chapter/major-unit entries plus their substantive H2 section headings; keep H3 and deeper headings out of the default navigation;
- keep front matter in the book itself, but omit it from `nav.xhtml` / `toc.ncx` until the first numbered structural unit such as `第一章`, `第一部分`, `Chapter 1`, or `Part I`;
- the first numbered body unit itself **is included**;
- source-side printed `# 目录` / `# 原书目录` is removed from EPUB content because reader apps already use EPUB navigation;
- title/subtitle duplicates are marked `unlisted`;
- table/figure headings, page numbers, and footnote anchors must never become navigation entries;
- no standalone final `注释` chapter appears in navigation.

For books where a substantive `导论` / `Introduction` / `Preface` should appear in navigation before Chapter 1, set:

```python
TOC_START_AT_FIRST_NUMBERED_UNIT = False
```

For current academic translation masters where H1 is the chapter/major-unit level and H2 contains substantive within-chapter sections, keep `TOC_DEPTH = 2` so readers can expand each chapter by one level. For unusually dense books whose H2 headings are merely editorial fragments, set `TOC_DEPTH = 1`. For H1 Parts + H2 Chapters, `TOC_DEPTH = 2` likewise preserves the meaningful two-level hierarchy. Do not include H3 boxes/subsections by default.

## 3. Do not insert a visible TOC page into the reading spine

Pandoc must still generate standards-compliant `nav.xhtml` and `toc.ncx`, but the navigation document itself should not become a normal page that readers encounter before the book.

Therefore the build intentionally does **not** pass Pandoc `--toc`. EPUB3 still receives `nav.xhtml`, while the navigation document stays out of the reading spine.

After Pandoc writes the EPUB, `build_epub.py` also performs defensive compatibility cleanup:

- remove any `itemref idref="nav"` from the OPF spine if one appears;
- remove Pandoc's legacy EPUB2 `<guide><reference type="toc" ...>` block;
- remove `epub:type="page-list"` navigation by default.

This cleanup matters because some importers/readers can over-expand legacy TOC/page-list structures and surface numeric/page/footnote links as an enormous pseudo-directory. Keep the standards EPUB3 `nav` and NCX; remove only the legacy or redundant structures above.

## 4. Normal workflow

When the user asks for EPUB from an assembled master:

1. locate final `master.md`, `cover_epub.jpg`, and `assets/` if present;
2. verify the master is assembled rather than untranslated Part files and the cover is the completed `COVER_SKILL` output;
3. change only necessary `USER SETTINGS` in `build_epub.py`;
4. run the build from the book project directory;
5. run the built-in structural QA, including cover-manifest/target checks;
6. inspect representative XHTML, `nav.xhtml`, `toc.ncx`, OPF structure, and the cover page when practical;
7. verify the delivered basename contains no spaces or literal `%20`;
8. deliver the final `.epub`.

When the project workflow requests EPUB and PDF together, EPUB is not a separate stopping point: continue in the same publishing turn through PDF QA, `zlibrary_metadata.md`, and final ZIP packaging.

## 5. Parameters normally changed

```python
INPUT_MD = "book_master.md"
OUTPUT_EPUB = ""
TITLE = "中文书名"
AUTHORS = ["Author Name"]
LANG = "zh-CN"

TOC_TITLE = "目录"
TOC_DEPTH = 2
SPLIT_LEVEL = 1
NOTES_TITLE = "注释"
TOC_START_AT_FIRST_NUMBERED_UNIT = True

HIDE_NAV_DOCUMENT_FROM_SPINE = True
REMOVE_LEGACY_TOC_GUIDE = True
REMOVE_PAGE_LIST_NAV = True
BRACKET_FOOTNOTE_NUMBERS = True

TOC_OMIT_HEADINGS = []
AUTO_OMIT_METADATA_TITLE_HEADINGS = True

ASSETS_DIR = "assets"
COVER_IMAGE = "cover_epub.jpg"
REQUIRE_COVER = True
```

`OUTPUT_EPUB = ""` derives a filename-safe output name from final Chinese `TITLE`. Spaces, literal `%20`, colons, and unsafe filename characters are normalized to underscores. In this project `cover_epub.jpg` is required by default; set `REQUIRE_COVER = False` only when the user explicitly requests a coverless EPUB.

`SPLIT_LEVEL = 1` is appropriate when chapter/major book units are H1. For older masters with H1 Parts and H2 Chapters, explicitly choose the hierarchy required by that master.

## 6. Narrow build-time source cleanup

The Lua filter may perform only these structural transformations:

- omit source-side `# 目录` / `# 原书目录` / `# Contents` blocks;
- omit the final source-side `# 注释` grouping shell after Pandoc has attached footnote definitions to正文 `Note` nodes;
- remove redundant internal headings whose exact text is `注释`;
- mark exact title/subtitle headings `unlisted`;
- when enabled, mark headings before the first numbered body unit `unlisted` while retaining the content itself.

It must not rewrite正文, quotations, statistics, tables, bibliography content, stable footnote definitions, or glossary decisions.

## 7. CSS policy for note markers

`epub_generic.css` must render正文 `.footnote-ref` links:

- at `font-size: 1em`;
- on the baseline (`vertical-align: baseline`);
- with normal inherited line height;
- without `<sup>` styling;
- with a small inline horizontal padding only for tap comfort.

The actual visible marker text is `[N]` written into the XHTML by post-processing; CSS is not the sole source of brackets or numbering.

The notes section may use a slightly smaller overall note font than正文, but the backlink number itself must be the same size and baseline as the surrounding note text.

## 8. Tables and images

Markdown tables pass directly to Pandoc. Do not convert them back to images solely for EPUB.

Images should already use relative paths such as:

```markdown
![图 3.1](assets/fig_03_01.png)
```

`build_epub.py` includes the project directory and `assets/` in Pandoc's resource path. If an image is missing, report the missing file rather than fabricating or redrawing it.

## 9. Build dependencies

Standard build requirements:

```text
Python 3
Pandoc
```

No persistent book-specific YAML is required; the script creates temporary metadata under `.epub_build/`.

## 10. Structural QA

A successful Pandoc exit code is not enough. The build must verify at minimum:

- EPUB ZIP integrity;
- `mimetype`, OPF package, `nav.xhtml`, and XHTML content exist;
- `mimetype` is first and stored uncompressed after repackaging;
- metadata title and requested authors are correct;
- exactly one OPF manifest item is marked `properties="cover-image"`, its target exists, and the cover is not a normal TOC entry;
- every正文 footnote reference is a local same-XHTML `#fnN` link;
- every正文 footnote reference displays literal `[N]` text;
- every referenced footnote target exists in that XHTML;
- note numbering begins at 1 and is contiguous within each XHTML chapter/chunk;
- every native footnote has a backlink to an existing正文 reference and displays literal `[N]`;
- `nav.xhtml` is not in the reading spine;
- no legacy OPF `<guide>` remains;
- no `epub:type="page-list"` navigation remains when the default cleanup is enabled;
- no navigation entry is a bare numeric/page/footnote marker;
- no `nav.xhtml` or `toc.ncx` target points to `#fnN` / `#fnrefN`;
- no standalone final `注释` navigation chapter remains;
- configured title/subtitle omissions are absent from the navigation TOC;
- all `nav.xhtml` and `toc.ncx` targets resolve;
- when `TOC_DEPTH >= 2` and the master contains substantive H2 headings, verify that H2 entries are nested under their parent H1 rather than flattened or omitted;
- suspicious table/figure navigation labels are reported.

If only structural QA is available, say so rather than claiming full visual-reader QA. For WeChat Reading or another specific reader, an actual import/screenshot remains the strongest compatibility test.

## 11. Error policy

Fix the narrowest actual problem. Typical fixes are limited to:

- correcting `INPUT_MD`, title, author, cover, or an `assets/...` path;
- selecting `TOC_DEPTH` / `SPLIT_LEVEL` appropriate to the real hierarchy;
- toggling `TOC_START_AT_FIRST_NUMBERED_UNIT` for a book whose front matter should be navigable;
- adding an exact heading to `TOC_OMIT_HEADINGS`;
- making a minimal Lua/CSS/post-processing adjustment for a genuinely different master structure.

Do not respond to EPUB build problems by retranslating or broadly rewriting the book.

## 12. Deliverable

The primary deliverable is the final `.epub`, normally named from the finalized Chinese title rather than `<BOOK_STEM>_中译.epub`. It must embed the completed `cover_epub.jpg` unless the user explicitly requests a coverless EPUB.

Do not deliver `.epub_build/`, extracted XHTML, temporary metadata, QA scratch files, or debugging artifacts unless the user asks. When explicitly asked for the Skill, provide the updated `EPUB_SKILL` directory/ZIP and, when useful, a patch against the previous Skill version.
