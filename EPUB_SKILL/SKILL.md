# Academic Book EPUB

## Scope

Use this skill after translation and final Markdown assembly are complete. The input is the single authoritative `master.md` produced by `TRANSLATION_SKILL`, normally with major book units at H1 and their internal sections at H2/H3. Images and image-based complex tables live under `assets/` and use relative paths.

This skill is for EPUB production only. Do not retranslate, rewrite, polish, renumber stable source footnote IDs, or create a second EPUB-specific body manuscript merely to fix presentation.

Bundled files:

```text
build_epub.py
epub_generic.css
epub_chapter_notes.lua
```

## 1. Core EPUB rule: chapter-end native footnotes

The master may keep the Translation Skill's assembled source shell:

```text
# 第一章 ...
正文[^ch01-001]
...
# 第二章 ...
正文[^ch02-001]
...
# 注释
## 第一章
[^ch01-001]: ...
## 第二章
[^ch02-001]: ...
```

For EPUB, do **not** rebuild these notes as one cross-book endnotes chapter.

`epub_chapter_notes.lua` removes the source-side `# 注释` organizational shell but does not rewrite Pandoc `Note` nodes. Pandoc's EPUB3 writer therefore emits the actual notes at the end of the XHTML chapter/chunk where they are cited, using native EPUB semantics such as:

```html
<a href="#fn1" class="footnote-ref" id="fnref1" epub:type="noteref">1</a>
...
<section class="footnotes footnotes-end-of-document" epub:type="footnotes">
  <aside epub:type="footnote" id="fn1">
    <p><a href="#fnref1" class="footnote-back" role="doc-backlink">1</a>. 注释正文……</p>
  </aside>
</section>
```

Required behavior:

- notes appear at the end of each chapter/chunk, not in one final Notes XHTML;
-正文 note links are local same-XHTML fragment links (`#fnN`), not cross-file `chXXX.xhtml#...` links;
- each note begins with a visible numbered backlink;
- numbering restarts at 1 for each chapter/chunk generated by Pandoc;
- preserve Pandoc EPUB3 `noteref` / `footnote` semantics because reader apps handle these more reliably than custom endnote markup.

Do not convert native `Note` nodes into custom `Link` nodes merely to control numbering or placement. If a reader has a genuine tap-target problem, prefer small CSS adjustments to `a.footnote-ref`; do not return to the old custom cross-file endnote model.

## 2. Normal workflow

When the user asks for EPUB from an assembled master:

1. locate final `master.md` and `assets/` if present;
2. verify it is already assembled rather than a set of untranslated Part files;
3. change only the necessary `USER SETTINGS` in `build_epub.py`;
4. run the build from the book project directory;
5. run the built-in structural QA;
6. when practical, inspect representative XHTML/nav output or a real reader screenshot;
7. verify the delivered basename contains no spaces or literal `%20`;
8. deliver the final `.epub`.

When the project workflow requests EPUB and PDF together, EPUB is not a separate stopping point: continue in the same publishing turn through PDF QA, `zlibrary_metadata.md`, and final ZIP packaging.

## 3. Parameters normally changed

```python
INPUT_MD = "book_master.md"
OUTPUT_EPUB = ""
TITLE = "中文书名"
AUTHORS = ["Author Name"]
LANG = "zh-CN"

TOC_TITLE = "目录"
TOC_DEPTH = 2
SPLIT_LEVEL = 1
NOTES_TITLE = "注释"

TOC_OMIT_HEADINGS = []
AUTO_OMIT_METADATA_TITLE_HEADINGS = True

ASSETS_DIR = "assets"
COVER_IMAGE = ""
```

`OUTPUT_EPUB = ""` derives a filename-safe output name from final Chinese `TITLE`. Spaces, literal `%20`, colons, and unsafe filename characters are normalized to underscores.

For the current Translation Skill, major book units are normally H1 and internal sections H2, so `SPLIT_LEVEL = 1` and `TOC_DEPTH = 2` are the defaults. This prevents H3 table/figure headings or minor subheads from flooding the navigation TOC.

Older masters can legitimately have another hierarchy, for example H1 Parts + H2 Chapters + H3 sections. For such a book, explicitly set `SPLIT_LEVEL = 2` and usually `TOC_DEPTH = 3`, as required by the actual master. Do not mechanically force the current defaults onto an older hierarchy.

`AUTO_OMIT_METADATA_TITLE_HEADINGS = True` keeps exact source headings matching the metadata title and its colon-separated main title/subtitle in the reading flow but marks them `unlisted`, avoiding duplicate title/subtitle entries in the navigation when Pandoc has already generated `title_page.xhtml`.

## 4. Source cleanup performed only at build time

The Lua filter may perform these narrow structural transformations without altering the authoritative master:

- omit source-side `# 目录` / `# 原书目录`, because EPUB navigation is generated automatically;
- omit the final source-side `# 注释` grouping shell after Pandoc has attached definitions to body `Note` nodes;
- remove redundant internal headings whose exact text is `注释` when native chapter footnotes will occupy that position;
- mark configured exact title/subtitle headings `unlisted` so they do not duplicate the generated title page in navigation.

It must not rewrite正文, quotations, statistics, tables, bibliography content, stable footnote definitions, or glossary decisions.

## 5. Navigation TOC

Treat EPUB navigation as a reading navigation structure, not as a dump of every Markdown heading.

Default current-master policy:

- H1 major book units appear in navigation;
- H2 meaningful internal sections appear in navigation;
- H3 and deeper headings are omitted unless the actual book hierarchy requires them;
- the source printed TOC is not duplicated;
- the assembled source `注释` shell does not appear as a standalone final navigation chapter;
- redundant book-title/subtitle headings should not appear below the generated title page;
- table titles or figure titles should normally not be navigation entries. If they appear because the master used them as headings, prefer the narrowest correction: lower `TOC_DEPTH` when hierarchy permits, or repair a genuine source-structure error in accordance with the Translation Skill rather than inventing EPUB-only prose changes.

Both EPUB3 `nav.xhtml` and legacy `toc.ncx` targets must resolve correctly.

## 6. Tables and images

Markdown tables pass directly to Pandoc. Do not convert them back to images solely for EPUB.

Images should already use relative paths such as:

```markdown
![图 3.1](assets/fig_03_01.png)
```

`build_epub.py` includes the project directory and `assets/` in Pandoc's resource path. If an image is missing, report the missing file rather than fabricating or redrawing it.

## 7. Build dependencies

Standard build requirements:

```text
Python 3
Pandoc
```

Check `pandoc --version` if the command is unavailable. No separate persistent YAML file is needed; the script generates temporary metadata under `.epub_build/`.

## 8. Structural QA

A successful Pandoc exit code is not enough. The build script must verify at minimum:

- EPUB ZIP integrity;
- `mimetype`, OPF package, `nav.xhtml`, and XHTML content exist;
- title metadata matches the requested title and requested authors are present;
- every正文 footnote reference is a local same-XHTML `#...` link;
- every footnote reference has a visible numeric marker;
- every referenced footnote target exists in that XHTML;
- native footnote numbering begins at 1 and is contiguous within each XHTML chapter/chunk;
- every native footnote has a backlink to an existing正文 reference and visible backlink number;
- no standalone final `注释` navigation chapter remains;
- configured title/subtitle omissions are absent from the navigation TOC;
- every `nav.xhtml` target resolves to a real XHTML file/fragment;
- every `toc.ncx` target resolves when NCX is present;
- possible table/figure headings in navigation are reported for review.

If only structural QA is available, say so rather than claiming a full visual-reader QA. For reader-specific issues such as WeChat Reading tap behavior, a screenshot or reader test is stronger evidence than browser rendering alone.

## 9. CSS policy for note links

`epub_generic.css` gives `.footnote-ref` a small inline-block tap area and renders it as a compact superscript-style marker. Native Pandoc output remains the semantic source of the link. The note-side backlink number remains visible and clickable.

Do not hide note numbers with CSS, do not depend on an ordered-list marker as the only visible note number, and do not use CSS-generated content as the only source of numbering.

## 10. Error policy

Fix the narrowest actual problem. Typical fixes are limited to:

- correcting `INPUT_MD`, title, author, cover, or an `assets/...` path;
- selecting `TOC_DEPTH` / `SPLIT_LEVEL` appropriate to the real hierarchy;
- adding an exact heading to `TOC_OMIT_HEADINGS`;
- making a minimal Lua/CSS adjustment for a genuinely different master structure.

Do not respond to EPUB build problems by retranslating or broadly rewriting the book.

## 11. Deliverable

The primary deliverable is the final `.epub`, normally named from the finalized Chinese title rather than `<BOOK_STEM>_中译.epub`.

Do not deliver `.epub_build/`, temporary metadata, extracted XHTML, QA scratch files, or debugging artifacts unless the user asks. When explicitly asked for the Skill itself, provide the updated `EPUB_SKILL` directory/ZIP and, when useful, a patch against the previous Skill version.
